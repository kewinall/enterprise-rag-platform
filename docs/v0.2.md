# v0.2 Feature Guide

Version 0.2 moves the project from a simple RAG MVP toward an enterprise document lifecycle
and retrieval experimentation platform.

## 1. Page and section metadata

PDF documents are parsed page by page. Markdown documents are split at headings before
chunking. Each stored chunk carries:

- document_id
- source
- content_type
- ordinal
- page when available
- section when available

The same metadata is returned in search results and answer citations.

## 2. Batch ingestion

Use POST /api/v1/ingest/batch with repeated files form fields. The default maximum is 20
files per request and is controlled by MAX_BATCH_FILES.

Each file is assigned a deterministic document ID from its source name. Re-ingesting the same
source replaces the old chunks so stale chunks do not remain after a document becomes shorter.

## 3. Document lifecycle

GET /api/v1/documents returns indexed document summaries.

DELETE /api/v1/documents/{document_id} removes every chunk belonging to that document.

PUT /api/v1/documents/{document_id}/reindex accepts a replacement file and preserves the
existing document ID.

## 4. Metadata filtering

Search and query payloads may include a filters object with document_id, source, content_type,
page and section. Multiple supplied filters use AND semantics.

Example request:

    {
      "query": "least privilege",
      "mode": "hybrid",
      "top_k": 5,
      "filters": {
        "source": "security-handbook.md",
        "section": "Identity and Access"
      }
    }

## 5. Retrieval modes and benchmark

The search and query APIs accept mode=vector or mode=hybrid.

Vector mode uses semantic Qdrant retrieval only.

Hybrid mode combines semantic retrieval and BM25 through Reciprocal Rank Fusion, then applies
the optional CrossEncoder reranker when ENABLE_RERANKER=true.

After ingesting both synthetic handbooks, run:

    make benchmark

The report compares Recall@K, MRR and average latency across the same evaluation cases.

## Scope boundaries

Version 0.2 intentionally does not yet add enterprise SSO, multi-tenancy, object storage,
RAGAS answer evaluation or a web UI. Those are roadmap items for later versions.
