# v0.2 功能指南 / v0.2 Feature Guide

**繁體中文**  
v0.2 將專案從基本 RAG MVP 推進成具備 Enterprise Document Lifecycle 與 Retrieval Experimentation 能力的平台。

**English**  
Version 0.2 moves the project from a simple RAG MVP toward an enterprise document lifecycle and retrieval experimentation platform.

## 1. Page / Section Metadata

**繁體中文**  
PDF 逐頁解析，Markdown 先依 Heading 分段。每個 Chunk 儲存 document_id、source、content_type、ordinal、page（若有）與 section（若有）。Search Result 與 Citation 都會回傳相同 Metadata。

**English**  
PDF documents are parsed page by page and Markdown documents are split at headings before chunking. Every chunk carries document ID, source, content type, ordinal, page when available, and section when available. The same metadata is returned in search results and citations.

## 2. Batch Ingestion / 批次匯入

**繁體中文**  
使用 POST /api/v1/ingest/batch，以重複的 files Form Field 上傳多檔。預設單次最多 20 檔，由 MAX_BATCH_FILES 控制。

**English**  
Use POST /api/v1/ingest/batch with repeated files form fields. The default maximum is 20 files per request and is controlled by MAX_BATCH_FILES.

**繁體中文**  
Document ID 由 Source Name deterministic 產生。相同 Source 再次匯入時會取代舊 Chunks，避免文件縮短後留下 Stale Chunks。

**English**  
Each file is assigned a deterministic document ID from its source name. Re-ingesting the same source replaces old chunks so stale chunks do not remain.

## 3. Document Lifecycle / 文件生命週期

- GET /api/v1/documents — 文件摘要 / indexed document summaries
- DELETE /api/v1/documents/{document_id} — 刪除該文件所有 Chunks / remove all chunks for a document
- PUT /api/v1/documents/{document_id}/reindex — 保留 Document ID 並替換內容 / replace content while preserving the document ID

## 4. Metadata Filtering

Search / Query Payload 可加入 / may include:

- document_id
- source
- content_type
- page
- section

多欄位採 AND Semantics / multiple fields use AND semantics.

範例 / Example:

    {
      "query": "least privilege",
      "mode": "hybrid",
      "top_k": 5,
      "filters": {
        "source": "security-handbook.md",
        "section": "Identity and Access"
      }
    }

## 5. Retrieval Mode 與 Benchmark / Retrieval modes and benchmark

**vector**
- 繁中：只使用 Semantic Qdrant Retrieval。
- English: semantic Qdrant retrieval only.

**hybrid**
- 繁中：Semantic Retrieval + BM25 → RRF → Optional CrossEncoder Reranker。
- English: semantic retrieval and BM25 through Reciprocal Rank Fusion, followed by the optional CrossEncoder reranker.

執行 / Run:

    make benchmark

輸出 / Output:
- Recall@K
- MRR
- Average Latency

## Scope Boundary / 範圍界線

**繁體中文**  
v0.2 尚未加入 Enterprise SSO、Multi-tenancy、Object Storage、RAGAS Answer Evaluation 或 Web UI；這些屬於後續 Roadmap。

**English**  
Version 0.2 intentionally does not yet add enterprise SSO, multi-tenancy, object storage, RAGAS answer evaluation, or a web UI. Those are later roadmap items.
