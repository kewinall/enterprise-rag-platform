04 · RAG Flow

Standard RAG 如何運作

1

Ingest

解析文件、保留 page/section/content_type，建立 deterministic document/chunk lineage。

2

Retrieve

同時執行 semantic vector search 與 BM25，再以 Reciprocal Rank Fusion 合併排名。

3

Ground

只將 tenant-scoped Top-K evidence 交給 LLM，回答附 citation 與來源定位。

05 · Advanced

Agentic RAG / Governed Agent Runtime

Safety boundary: LLM 只能「提出」Tool Call；Server-side Registry、RBAC、Tenant 與 Approval Policy 才能決定是否執行。 專案沒有開放 arbitrary shell、raw SQL、generic HTTP、eval/exec、cloud-admin 或 secret-read tool。
06 · Security

企業安全模型 / Security Model

ID

Identity

OIDC/JWT 或 API Key Demo；Principal 由可信任驗證層建立。

RB

RBAC

Viewer / Editor / Admin，Tool 與 API 各自檢查角色。

T

Tenant

tenant_id 從 Principal 衍生，不接受 Client 任意覆寫。

✓

Approval

破壞性 Agent Tool 使用 TTL、tenant/role re-check 與 single consumption。

ControlDesignWhy it matters
Prompt injection heuristicStandard + Agent endpoints pre-checkRegression boundary, not complete DLP/guardrail replacement
Tool allowlistUnknown planner tools discarded/rejectedPrevents arbitrary capability expansion
Audit minimizationNo question/prompt/answer body by defaultReduces sensitive-data exposure
Trace minimizationOperational metadata onlyObservability without prompt leakage
Budget / rateToken/cost budget + Redis rate limitControls runaway agent/model usage

13 · FAQ

常見問題 / FAQ

這和一般 RAG Demo 最大差別？

一般 Demo 通常停在 upload → vector search → chat。本專案額外涵蓋 document lifecycle、hybrid retrieval、evaluation、tenant isolation、object storage、audit/trace、OIDC/RBAC、agent approval、Kubernetes 與 offline delivery。

為什麼 v0.6 還有 MCP / Agent，但定位卻是 Knowledge AI？

MCP / Agent 是進階整合示例，用來證明 Knowledge Layer 可以被更高階 Agent Runtime 消費；完整 Tool Platform 與 DataOps Reasoning 分別由其他 Portfolio Repo 負責。

目前是否代表完整 Production SaaS？

不是。本 Repo 是 production-oriented reference implementation。正式環境仍需企業 IdP、Gateway/WAF、DLP/Malware scanning、KMS、SIEM、managed datastore、SLO/DR 與組織內部治理流程。

有沒有真實客戶或公司資料？

沒有。Repository 使用 synthetic/generic sample，避免公司、客戶、內部 URL、Credential、Schema 與敏感資料。
